# 🤖 给 Agent 的开工说明（队友的 AI 助手请读这一页）

> 你是一位队友的 WorkBuddy AI 助手。你的主人刚加入 `widework` 协作仓库。
> **本文件是给你读的**，不是给你的主人读的。请严格按照这里的规则替他干活。
> 人类版说明见 [`docs/给队友的开工指南.md`](docs/给队友的开工指南.md)（可以直接甩给你的主人看）。

---

## 你的主人是谁、你要干什么

- 仓库：`https://github.com/a3230038469/widework`（**公开仓库**，但你主人已被加为协作者，可以推代码）
- 项目：AI 向善实战营第四期 ·零废弃数字化知识库「对外版」
- 你主人的角色：**认领任务 → 用 WorkBuddy 干活 → 交付成果到 GitHub**
- 你要负责：**在 WorkBuddy 里把活干完，并按规范整理成交付成果**

## 🚨 五条铁律（违反会被 PR 打回）

| # | 铁律 | 为什么 |
|---|---|---|
| 1 | **只改本任务目录内的文件** | 四个组并行开发同一产品，跨界改动会撞车 |
| 2 | **不许自造字段名/API 路径/事件名** | 契约是全队"插座标准"，自造 = 别人的插头插不上 |
| 3 | **提交信息必须带 #任务号** | 格式：`feat: 完成登录页表单校验 #12` |
| 4 | **不许直接改契约** `docs/contracts/` | 契约 10/4 冻结，改动要走变更流程 |
| 5 | **不许提交垃圾文件** | `node_modules/` `dist/` `.env` 锁文件 一律不进仓库 |

## 📋 标准工作流（4 步）

### 第1 步：读任务

你的主人会告诉你任务编号（如"我领的是 #12"）。若他没给，先做这一步：

```bash
# 列出所有待领取任务
gh issue list --repo a3230038469/widework --label "状态/待领取" --json number,title,labels
# 看某个任务的完整内容（含验收标准）
gh issue view 12 --repo a3230038469/widework
```

**拿到任务后必须先读这三样，缺一不可：**

1. **任务 Issue 全文** —— 里面有「交付物」和「验收标准（3 例）」，这是你干活的依据
2. `docs/contracts/C3-API协议.md` —— 你要调的接口长什么样
3. `docs/contracts/C2-字段映射表.md` —— 字段叫什么名字
4. （若涉及埋点）`docs/contracts/C4-埋点事件表.md`

> **契约看不懂或有歧义 → 停下来问你主人**，让他去群里找鲍志广（集成负责人）确认。
> **不要猜、不要自己造、不要"先这么写着等后面改"。**

### 第 2 步：开工前先自检（避免白干）

```bash
# 确认主分支没被别人改坏
git fetch origin && git log --oneline origin/main -5
```

**目录边界（只准动自己任务目录）：**

| 板块 | 你能动的目录 |
|---|---|
| F0 地基 | `docs/` `.github/` 根目录配置 |
| F1 前端 | `frontend/src/pages/<你的页面>/` |
| F2 后端 | `backend/app/routers/<你的接口组>.py` |
| F3 引擎 | `deploy/` 中 WeKnora 相关配置 |
| F4 内容 | `content/` |
| F5 看板 | `stats/` |
| F6 部署 | `deploy/` |

> 唯一例外：`backend/app/rag_proxy.py` 是全仓库唯一允许出现引擎地址的文件，**只有 F0 能改**。

### 第 3 步：干活

- 按任务 Issue 的「交付物」清单产出文件，**目录层级严格按模板**
- 参考同板块已完成任务的代码风格（`gh api repos/a3230038469/widework/contents/<目录>` 可直接读远端文件）
- 阻塞了就说出来，**别硬凑一个假完成品交上去**

### 第 4 步：交付（最容易出错的一步）

你的主人做完活后，把下面这段话**原样发给你**，你负责整理成果：

```
我领的任务是 GitHub 上的 #<任务号> <任务名>。请按下面要求整理交付成果：

1. 把本任务的全部代码文件整理好，按任务要求的目录结构组织
2. 对照任务 Issue 里的「验收标准」3 条，逐条自查并告诉我：通过 / 没通过 / 为什么
3. 你用到的接口字段名，必须是 docs/contracts/ 里已定义的（不许自造）
4. 给我一个交付总结，包含：
   ① 文件清单：每个文件名 + 它应该放到仓库的哪个路径
   ② 一段提交说明，格式：feat: <简述> #<任务号>
   ③ 验收自测结果（第 2 条的结论）
5. 自我检查：确认没有改动本任务目录以外的文件
```

**你必须交付给主人的东西（4 样）：**

1. **文件清单**：每个文件 + 它该放哪
2. **提交说明**：`feat: 简述 #任务号`
3. **验收自测结论**：逐条通过/未通过/未测（**没测就写未测，禁止编造**）
4. **一段可直接复制粘贴的 PR 描述**：照 `.github/PULL_REQUEST_TEMPLATE.md` 的结构填好

## 🔧 沙箱能不能直连 GitHub？两条路都支持

方案文档里写"沙箱无法直连 GitHub，成果需经主人电脑中转"，但**实测部分环境已可直连**。请先自检：

```bash
gh auth status 2>&1 | head -5   # 有账号 = 已登录可用
```

| 情况 | 你该怎么做 |
|---|---|
| **已登录** | 直接本地建分支提交推送（推荐，见下） |
| **未登录/连不上** | 把文件整理好，让主人在网页上拖拽上传（姿势 A） |

### 走直连路径（已登录时）

```bash
cd <你的工作目录>
git config user.name "<主人GitHub用户名>"
git config user.email "<主人GitHub邮箱>"

# 拉最新main，避免覆盖别人的改动
git clone https://github.com/a3230038469/widework.git && cd widework
git checkout -b feat/<任务号>-<板块>-<简述>    # 例：feat/12-F1-login-page

# 提交
git add <你只改动的那些文件>       # 务必只 add 自己的文件
git commit -m "feat: <简述> #<任务号>"

git push -u origin feat/<任务号>-<板块>-<简述>
```

推送成功后告诉主人去网页提 PR。**如果 push 报认证错误**，让主人在终端执行一次 `gh auth setup-git` 即可修复。

### 走网页路径（连不上时）

告诉主人：

1. 打开仓库对应目录：`https://github.com/a3230038469/widework/tree/main/<你的目录>`
2. 点 **Add file → Upload files**，把你整理好的文件拖进去
3. 填写提交说明（必须带 `#任务号`）
4. 直接在 `main` 上提交（**仅限连不上 git 时**；直连情况下请务必走分支+PR）

## 🆘 卡住了怎么办

| 情况 | 怎么办 |
|---|---|
| 契约看不懂/有歧义 | 停下→ 让主人群里问鲍志广，**不要自己改契约** |
| 任务做不了 | 在 Issue 下评论"释放"，无损退出，换一个 |
| 与别人代码冲突 | 重新 `git fetch && git pull`，或请鲍志广协调 |
| Mock 数据和真后端不一致 | 提 Issue 说明，**这是 bug 该有人修**，别自己将就 |
| 72 小时没提交 | 任务自动释放回池，先到先得 |

**记住一句话：宁可问，不要猜。猜错了要返工，返工比问更慢。**
