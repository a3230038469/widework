# 队友开工指南（人类版·3 分钟读完）

> 零基础写给不熟悉 Git 的同学。你**不需要懂 Git**，按下面的做就行。
> 你也可以把这份直接甩给你的 AI 助手（它读得懂），或者看 [`给Agent的开工说明.md`](给Agent的开工说明.md)。

---

## 一、你是什么角色

你是**任务领取人**。流程固定是四步：

```
领任务 → 在 WorkBuddy 里用助手干活 → 把成果交到 GitHub → 集成负责人验收合并
```

**"我来合并"这一环不用你操心**——你交上 PR 就行，鲍志广（集成负责人）负责审和合并。

---

## 二、开工前一次性准备（每人 10 分钟）

| 步骤 | 做什么 | 说明 |
|---|---|---|
| 1 | **注册 GitHub 账号** | 打开 https://github.com/signup 用邮箱注册 |
| 2 | **把用户名发群里** | 就是 `github.com/你的用户名` 里那一串，格式如 `zhangsan123` |
| 3 | **接受协作者邀请** | 邀请会发到你注册时的邮箱，**记得看垃圾邮件箱** |
| 4 | 完成 GitHub 账号的邮箱验证 | 不验证无法提 PR |

> 🔒 **密码、验证码、Token 一律你自己在 GitHub 官方页面输入，不要发给任何人（包括 AI 助手）。**

### 关于 Git 本身

**这个仓库你完全不需要手动敲 Git 命令。** 你只需要：

- 知道代码放在仓库的哪个目录（任务 Issue 里会写清楚）
- 知道怎么把文件传上去（你的助手会帮你）

你的 AI 助手读 [`docs/给Agent的开工说明.md`](给Agent的开工说明.md) 后，就知道怎么干了。**这也是我们建议你做的事：把这句发给它**

> 读 https://github.com/a3230038469/widework/blob/main/docs/给Agent的开工说明.md，然后按里面的流程帮我领任务和交付。

## 三、领任务（1 分钟）

打开仓库的 **Issues** 页签：

https://github.com/a3230038469/widework/issues

筛选条件：标签选 **`状态/待领取`**

### 怎么挑任务

| 标签 | 含义 | 新手建议 |
|---|---|---|
| `难度/易` | 有手把手教程 | ✅ **优先领这些** |
| `难度/中` | 需要自己查文档 | 有信心再领 |
| `难度/难` | 有技术门槛 | 先别领 |
| `P0` | demo 必须 | 优先 |
| `P1` | 结项前要完成 | 次优先 |
| `P2` | 有余力再做 | 最后考虑 |

### 怎么"领取"

每个任务 Issue 下面做三个动作：

1. 右上角 **Assignees** 点自己 → 把自己填进去
2. 右侧 **Labels** 把 `状态/待领取` 换成 `状态/进行中`
3. 在评论框写 **"我认领"** 并提交

### 两条纪律

- **一人同时最多 2 个"进行中"** —— 别贪多，做不完
- **72 小时没提交会自动释放回池** —— 先到先得，别人能捡走

## 四、干活（在 WorkBuddy 里）

1. 打开你领的任务 Issue，**完整读一遍**（有交付物清单、验收标准、接口依赖）
2. 把 Issue 里的**验收标准**和**接口依赖**两部分复制下来
3. 按下面这句话发给你的助手：

```
我领的任务是 GitHub 上的 #<任务号> <任务名>。请按下面要求整理交付成果：

1. 把本任务的全部代码文件整理好，按任务要求的目录结构组织
2. 对照任务 Issue 里的「验收标准」3 条，逐条自查并告诉我：通过 / 没通过 / 为什么
3. 你用到的接口字段名，必须是 docs/contracts/ 里已定义的（不许自造）
4. 给我一个交付总结，包含：
   ① 文件清单：每个文件名 + 它应该放到仓库的哪个路径
   ② 一段提交说明，格式：feat: <简述> #<任务号>
   ③ 验收自测结果
4. 自我检查：确认没有改动本任务目录以外的文件
```

4. 助手会帮你把活干完，并把成果整理好给你

---

## 五、交成果（你唯一需要动手的地方）

助手会给你一份**交付总结**（文件清单 + 提交说明 + 验收结论）。你接下来做：

### 情况 A：你的助手能直连 GitHub（推荐）

助手会直接帮你推代码，然后你只需：

1. 打开仓库的 **Pull requests** 页签
2. 找到你刚提的 PR（可能需要刷新一下）
3. 点 **Compare & pull request** 补齐标题和描述（助手会给你现成的文案，粘贴进去）
4. **把 PR 链接发群里**，告诉鲍志广来验收

### 情况 B：助手连不上 GitHub（沙箱网络限制）

助手会把文件给你，你手动上传：

1. 打开仓库对应目录，例如
   `https://github.com/a3230038469/widework/tree/main/frontend/src/pages`
2. 点 **Add file → Upload files**
3. 把文件**拖进去**
4. 填写提交说明，**必须带 #任务号**（例：`feat: 完成登录页表单校验 #12`）
5. 提交后到 Pull requests 页签提 PR

> ⚠️ 情况 B 下你是直接提交到 `main` 的，请**务必确认只上传了自己任务目录的文件**，别误传别人的。

## 六、你的 PR 会被怎么审（了解就好，不用紧张）

集成负责人（鲍志广）按三道闸审你：

| 闸 | 谁负责 | 你要做的 |
|---|---|---|
| ① 机器自动检查 | CI 自动跑 | 代码能跑通、提交信息带 #任务号、没越界改文件 |
| ② 契约对照 | 负责人人工看 | PR 描述里勾选的字段名和契约一致 |
| ③ 审批合并 | 负责人点合并 | —— |

**被要求修改怎么办？** 正常流程！在 PR 里回复负责人指出的问题 → 改 → 再推一次。这不是出错，是协作流程的一部分。

---

## 七、几条重要提醒

| 提醒 | 原因 |
|---|---|
| **契约（C2/C3/C4）是全队插座标准** | 你自造字段名，队友的代码就插不上你的接口 |
| **契约 10/4 冻结** | 冻结后要改必须走变更流程并广播，别自己改 |
| **只改自己任务目录** | 四个组并行，跨界改动会撞车 |
| **Mock 先行** | 前端不等后端、后端不等引擎，大家并行开工，靠 Mock Server 联调 |
| **有疑问先问，别猜** | 猜错了要返工，返工比问更慢 |
| **干不了可以"释放"** | Issue 下评论"释放"，无损换任务 |
